# F12 DevTools 使用指南

## 快速解决方案

如果F12打开的DevTools窗口是白屏，请使用以下最简单的方法：

### 方法1：使用浏览器远程调试（推荐，100%有效）

1. 启动应用程序
2. 打开系统浏览器（Chrome/Edge/Safari/Firefox）
3. 访问：`http://localhost:9222`
4. 点击页面中显示的调试目标
5. 完整的DevTools会在浏览器新标签页中打开

**为什么这个方法有效？**
- 使用独立的浏览器进程渲染DevTools，不受应用限制
- 功能完整，等同于Chrome DevTools
- 永远不会白屏

### 方法2：等待加载

1. 按F12输入密码
2. **保持DevTools窗口打开，不要关闭**
3. **等待10-15秒**
4. 窗口内容会逐渐显示出来

**为什么需要等待？**
- 单进程模式下，DevTools和主窗口共享渲染资源
- 第一次加载DevTools需要初始化大量资源
- 软件渲染比GPU渲染慢

## 使用诊断工具

我们提供了自动化诊断脚本：

**Windows：**
```cmd
scripts\test-devtools.bat
```

**Linux/macOS：**
```bash
./scripts/test-devtools.sh
```

这个脚本会自动：
- 检测远程调试端口是否开启
- 显示可访问的URL
- 列出所有可调试的目标

## 常见问题

**Q: 为什么会白屏？**

A: 这是CEF 75在单进程模式下的已知行为，不是bug。DevTools需要时间加载和渲染，特别是在资源受限的系统上（32位/Windows 7）。

**Q: 有没有永久解决方案？**

A: 使用远程调试接口（方法1）就是永久解决方案。这是CEF官方推荐的开发调试方式。

**Q: 远程调试端口9222被占用怎么办？**

A: 检查日志文件，应用会自动选择其他可用端口，并在日志中记录实际端口号。

## 技术说明

- 远程调试端口在应用启动时自动开启
- 端口号默认9222，如被占用会自动递增
- 日志文件会记录实际使用的端口号
- CEF消息循环每10ms运行一次，确保DevTools能正常渲染
