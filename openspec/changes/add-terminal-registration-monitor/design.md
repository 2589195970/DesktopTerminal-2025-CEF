# Design

## Context

`UMTerminalService` 以 LocalSystem 运行，负责开机注册、心跳和命令接收。配置和注册凭据在 `%ProgramData%\UMTerminal`。Windows 用户登录后运行独立的 Qt 托盘工具。

## Goals / Non-Goals

**Goals:** 本机准确显示注册进度和异常。现场人员使用普通账户即可查看、筛选和导出诊断记录。

**Non-Goals:** 修改学校服务器协议、考试端界面或考试控制。服务控制继续使用现有管理员入口。

## Decisions

- 服务把状态和运行事件写入 `%ProgramData%\UMTerminalStatus`。该目录由系统账户创建。系统和管理员可写，普通用户可读。运行事件使用固定字段与错误类别。
- 托盘读取 Windows 服务状态和快照中的进程标识、更新时间和最近心跳时间。快照以原子方式替换。Windows 服务状态优先，超过 90 秒的心跳视为过期。
- 托盘面板沿用确认稿的圆角标题栏、状态卡、下划线页签和底部操作栏。运行日志用同一套表头、分隔线和状态配色，点开异常可查看起止时间和次数。
- 一次连续故障保留唯一事件标识。在状态快照中更新累计次数，故障结束后落盘汇总。读取时按标识合并。网络成功和错误原因变化决定事件边界。
- 日志使用 UTC 时间写入，界面与导出按 Windows 本地时间显示。每类日志以日期、大小和文件数为界管理。
- NSIS 发布托盘可执行文件、登录启动项和开始菜单入口。卸载移除入口和该工具的状态及运行日志。运行日志使用服务已经产生的注册、绑定和心跳结果。

## Risks / Trade-offs

- 状态目录不可用时，托盘提示状态不可用。注册服务继续处理网络请求。
- Windows 可以隐藏托盘图标。开始菜单是固定入口。
- Windows 7 SP1 x86 与现代 Windows x64 均使用 Qt 5.15 和现有安装包的依赖。
